# Plurals, numbers and language switching (round 10d)

How netwarden says "1 device" / "2 devices" in twelve languages, writes numbers the way each
language does, and changes language without a reload. Contributor notes; the user-facing
side is simply "every text follows the selected language".

## Count texts (plurals)

A text with a count is ONE base key in CLDR's "other" form plus its other forms:

| key | en | ru |
| --- | --- | --- |
| `intent.new_head` | `**{n} new devices** ({when}):` | `**{n} новых устройств** ({when}):` |
| `intent.new_head_one` | `**{n} new device** ({when}):` | `**{n} новое устройство** ({when}):` |
| `intent.new_head_few` | - | `**{n} новых устройства** ({when}):` |
| `intent.new_head_many` | - | `**{n} новых устройств** ({when}):` |

- English decides what a count text is: a key with `<key>_one` in `en.json`.
- Russian (and Polish, if it is ever added) also needs `_few` and `_many`
  (`i18n.PLURAL_FORMS`). French, Brazilian Portuguese and Hindi use `_one` for 0 and 1.
- Chinese, Japanese, Korean and Indonesian have no grammatical number: their `_one` is the
  base text, and the base is always used.
- A `_one` form may drop the count (`"{n} times"` / `"once"`) ONLY in a language whose "one"
  means exactly 1 (en, de, es, ...). Russian "one" is also 21, 31, ...; French, Portuguese
  and Hindi "one" is also 0: there the form keeps `{n}` ("{n} раз", "{n} fois"). `_few` /
  `_many` never drop it. The checker enforces both (`i18n._one_is_only_1`).

**Python:** `i18n.tn(key, count, lang, **kw)` picks the form; `{n}` is the count unless you
pass a formatted one (`tn(key, total, lang, n=i18n.num(total, lang))`). `i18n.t(key, lang,
n=3)` also picks the form when `n` is an integer and the key is a count text. A count under
another name (`{queries}`, `{hosts}`) needs `tn()`: the test scans for it.

**app.js:** `TN(key, n, o)` uses `Intl.PluralRules(S.lang)`, falls back to the base key and
formats `{n}`. A literal `T('<count key>'` is a test failure.

**Several counts in one text** cannot have one plural form. Write them in the colon style:
`"Devices: {devices} · Lookups: {queries}"`.

**The checker** (`python3 -m netwarden.i18n --check`, run by `tests/test_i18n.py`):

- `plural_missing`: an English text puts a count before a plural noun (`count_texts()`)
  without `_one`. A count that is never 1 (a retention minimum, a fixed port list) goes
  into `i18n.PLURAL_FIXED` with the reason.
- `plural_forms`: a Russian `_few` / `_many` form is missing.
- `plural_hedge`: "device(s)", "Gerät(e)", "устройств(о)" in any language (but not
  `http(s)`).

**The tests:** `tests/test_round10d.py` checks that Python's rules equal the browser's
`Intl.PluralRules` (it needs node; skipped without it).

## Numbers

`i18n.num(value, lang, decimals)` writes numbers in server texts the way
`Intl.NumberFormat` does in the browser:

- `1,234.5` in English; `1.234,5` in German; `1 234,5` in French (narrow no-break space);
- Spanish and Russian group only from 5 digits;
- Hindi uses lakhs (`12,34,567`).

`brain.human_bytes(n, lang)` and `nethealth`'s ms / % use it. Units stay `MB`, `GB` and `ms`
in every language.

## Lists and language names

- Lists are joined with `list_sep` (`, ` in most languages, `、` in Chinese and Japanese).
  This applies in Python (offline answers) and in app.js.
- A tool chip in the chat stores the separator of the language its answer came in
  (`x.sep`), so an earlier English message keeps "Behavior change, last 24 h" after a
  switch to Chinese.
- `langName()` writes a language's name in the dashboard's language
  (`Intl.DisplayNames`), with the native name as a fallback. The language menu itself
  shows native names.

## Language switching

`setLang()` loads the new strings, forgets every ETag (`forgetTags()`, round 10c), re-renders
the chrome, then runs `langChanged()`: ONE table, `LANG_DEPS` in app.js, of everything that
holds the previous language's words:

    [what, when (on screen or cached?), how to get it again]

Each source is fetched at most once per switch, and only when it is shown or kept.
`tests/js/lang_switch_test.js` cuts the block out of app.js and runs it against page states
(Overview, Settings with an open log and preview, a drawer, the palette, a remote viewer, ...).
`tests/test_round10d.py` checks that every `load*()` in app.js is in `LANG_DEPS`, in
`refresh()`, or on its list of loaders that hold no translated text.

**Adding something that shows server text:** if it is not part of `refresh()`'s datasets,
add a `LANG_DEPS` row, and a node check for when it runs.

### Browser checklist (after changing translated UI)

Use the static demo (`scripts/build_static_demo.py --out DIR --langs en,zh-Hant,ru`, served
under `/netwarden/` on 127.0.0.1:8799) or your own `--offline-ai` server on a copy of the
demo DB. Check at 1280x800 and 375x812:

1. Open the palette, type a query that finds a setting (e.g. "retention"), and switch the
   language with the palette open. The results, including Settings, change without typing.
2. Open a service or domain drawer and switch en -> zh-Hant -> en -> ru: the drawer follows
   each time.
3. AI page: ask two suggested questions, then switch. Earlier messages keep their language
   under the note, which names that language in the new one; the suggested questions and
   the "Looked up" labels are in the new language.
4. Settings with the palette open: the network panel shows each request at most once per
   switch.
5. ru: counts read "1 устройство", "3 уведомления", "12 запросов". No "(s)" anywhere, and no
   console errors.
